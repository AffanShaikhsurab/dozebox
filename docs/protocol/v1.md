# Payload protocol v1

The contract between a payload and the box agent: HTTP/1.1 with JSON bodies over the payload's Unix socket
(`DOZEBOX_SOCKET`). Field-level tables for every request, response, event, record and config document are generated
in [docs/reference/protocol-v1.md](../reference/protocol-v1.md); the JSON Schema files are in
`packages/protocol/schema/v1/`.

## Endpoints

| Method and path                                                | Purpose                                                      | Success                                   |
| -------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------- |
| `GET /v1/hello`                                                | Versions, features, limits, deprecations                     | 200 `Hello`                               |
| `GET /v1/status`                                               | Box phase, instance, disk, idle verdict, own holds and wakes | 200 `Status`                              |
| `GET /v1/events`                                               | Server-sent events                                           | 200 `text/event-stream`                   |
| `PUT /v1/holds/{id}`, `DELETE /v1/holds/{id}`, `GET /v1/holds` | Holds                                                        | 200 `Hold`, 204, 200 `HoldList`           |
| `POST /v1/beats`                                               | Progress and loop beats                                      | 204                                       |
| `PUT /v1/wakes/{id}`, `DELETE /v1/wakes/{id}`, `GET /v1/wakes` | Wake requests                                                | 200 `Wake`, 204, 200 `WakeList`           |
| `PUT /v1/presence/{id}`, `DELETE /v1/presence/{id}`            | Presence                                                     | 200 `Presence`, 204                       |
| `POST /v1/attention`                                           | Tell a human                                                 | 202 `AttentionAccepted`                   |
| `PUT /v1/health`                                               | Self-reported health                                         | 204                                       |
| `POST /v1/sleep`                                               | A person asked to sleep now                                  | 202 `SleepAccepted` or 409 `SleepRefused` |

Errors use `ErrorBody` with a `code`, a `message`, an optional `field` and `retryable`.

## Versioning

| Thing                      | Version carried                  | Compatible change (minor)                                                                                              | Breaking change (major)                                                                                                             |
| -------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Protocol endpoints         | Path `/v1/...`; minor in `hello` | New endpoint; new optional request field (behind a feature or minor); new response field; new enum value in a response | Removing or renaming a field, endpoint or enum value; changing a default; making an optional request field required; changing units |
| Records                    | `v` in each record               | New optional field                                                                                                     | Anything else: write `v: 2`                                                                                                         |
| Control API                | Path `/v1/...`                   | Same as protocol                                                                                                       | Same as protocol                                                                                                                    |
| Payload definition, config | `"schema": 1`                    | New optional key with a default                                                                                        | Anything else                                                                                                                       |

1. **Readers tolerate additions.** Clients ignore unknown response fields and map unknown enum values to a fallback:
   `phase` reads as `serving`, `severity` as `notify`, payload `health` as `unknown`, control `state` as `running`,
   and summary or alert-path `level` as `info`. `normalizeStatus`, `normalizeEvent` and `normalizeControlStatus` in
   `@dozebox/protocol` do this; an unknown event becomes `{ type: "unknown" }`.
2. **The agent is strict about requests.** An unknown field is `400 unknown_field`. A client learns what it may send
   from `hello`.
3. **Enum growth needs readers first.** A new enum value ships in the protocol package one minor before the agent
   emits it.
4. **Deprecation.** Mark it in `hello.deprecations` and with `Deprecation` and `Sunset` headers, keep it working for
   at least 2 minors and 6 months, and remove it only in the next major. Agent N+1 serves `/vN` and `/vN+1` side by
   side for at least 12 months.
5. **Payload and agent versions are independent.** A payload built for 1.3 works on agent 1.0 by sending only 1.0
   fields after reading `hello`.

A reader that sees a record with a higher `v` than it knows treats the record as missing. It never guesses.
